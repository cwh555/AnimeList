# AnimeList Protocol

This is the authoritative agreement for language boundaries and compatibility. Markdown and YAML frontmatter remain the source of truth.

## Language boundaries

AnimeList interface locales: zh-TW, zh-CN, en, ja, ko.

| Surface | Language behavior | Storage |
| --- | --- | --- |
| Workspace UI, buttons, notices, forms | Localize through i18n catalogs | No data rewrites |
| **Obsidian Settings and Settings-launched dialogs** | **Always English, including progress and errors** | No localization of Settings prose |
| Provider-category tags in the known dictionary | Translate labels for display | Keep original canonical values |
| User tags and custom text | No automatic translation | Preserve input |
| Author/studio/creator names | No automatic translation | Preserve source/user text |
| Newly imported work titles | Select known provider-labeled title for interface locale | Persist chosen title and provenance |
| Existing note titles | **Never change on interface locale switching** | Persist until user explicitly edits or migrates |

Legacy tag limitation: historical genres mixes provider terms and manually entered tags. A user tag that equals a recognized provider dictionary key may display a localized label even though the stored value is unchanged. Resolving such ambiguity requires a separate source-provenance migration.

## Title provenance

- title: current stored/user-controlled title.
- title_original: source-original title.
- title_romaji: romanized spelling when available.
- title_aliases: historical names and search aliases.
- title_localizations: optional locale-to-verified-title dictionary from the provider.
- title_script_conversions: optional locale-to-OpenCC-converted-name dictionary. For a **new import**, the initial create form may adopt an offline-converted name and persist its provenance if the user saves the form without replacing that title. For **existing notes**, any title update or conversion requires the user's explicit review and acceptance. A conversion never claims to be an official provider localization; manual title edits never acquire spurious conversion provenance.

Bangumi name_cn is Simplified Chinese, not necessarily an official Taiwanese Traditional title. A verified Traditional title must have explicit provenance from Bangumi infobox. AniList provides English/native/romaji, with JP/KR native attribution only if origin information supports it. Never invent an official translation from unlabelled synonyms. OpenCC (opencc-js 1.4.2) is available **only** as an offline Chinese-script-conversion fallback. It is **not** a provider-verified localized title or general machine translation.

## Cleanup responsibilities

- **Version updates**: fixes for artifacts generated by older plugin templates (e.g. duplicate default cover embeds).
- **Legacy data**: opt-in changes to user-owned notes (filenames, metadata and localized titles).

## Existing-title update workflow

Settings → Updates & cleanup → Existing media titles → Preview title updates.

1. User selects target language; *all* Settings dialogs, button labels, status messages and errors remain English.
2. The scanner shows each work's name, path and result as it completes. All scanned work results remain visible in the review list, not just proposals.
3. Title candidates come from previously verified stored localizations, exact provider IDs, or exact provider IDs preserved in source URLs. Bangumi title-only requests omit the separate person/studio endpoint.
4. For an AniList-only work needing a Chinese name, a unique original-title matching Bangumi search result can be proposed **for explicit review only**. Ambiguous or mismatched-year results are rejected; such proposals are unchecked by default.
5. Every work has a scan status: ready, review, unchanged, no-source, no-translation, custom-title, ambiguous, or lookup-failed. Live scanning shows each status; the completed review lists **only actionable changes**, with aggregate counters for other outcomes. A Bangumi result with Simplified Chinese but no verified Traditional Chinese title may provide an OpenCC conversion as an **unchecked review-only proposal**; the UI must never mislabel it as an official translation. No Chinese source means a visible missing-translation status.
6. The user reviews old → proposed name and selects works. Preview never writes.
7. On apply, recheck source identity, original title and file modification time. Write only title, optional missing title_original, title_aliases, title_localizations and accepted title_script_conversions, through Obsidian processFrontMatter.
8. Do not alter filenames, Markdown bodies, headings, personal scores, progress, authors, tags, covers, rankings, or unrelated YAML. This protects Obsidian links and note ownership.
9. Each write outcome is reported. Closing the modal after confirmation does not cancel already-running writes, and a final notification still appears.

Requests are paced with shared minimum spacing (350ms by default) and bounded concurrency (three workers by default, maximum four); duplicate provider IDs are fetched once per scan. API failures are shown with their work and reason, never silently swallowed.

## Compatibility

Older notes without title_localizations remain usable and are not automatically modified. Changing the interface language must never trigger a data migration. Filename reconciliation is an entirely separate, manually previewed compatibility tool.

## Verification

Behavior tests must cover source-URL IDs, stored variants, AniList-only records, cross-provider ambiguity, custom titles, missing translations, 429 errors, cancellation, stale preview protection, bounded concurrency, and unrelated frontmatter preservation. Human Test Vault validation must additionally check Settings English, large-library scanning responsiveness, and exact update previews.

## Provider-neutral title selection

A single typed selector owns the rules in `src/domain/media-title-localization.ts`. The data adapter in `src/data/media-title-service.ts` applies it to `ExternalMediaResult`, without modifying source identity, metadata, author/studio names, or authoritative title variants. Each provider normalizer **only extracts title evidence**; all three then use the same adapter. The create-note enrichment boundary reapplies this selection before the form is populated, so a second API call cannot silently revert the name.

For **new** imports, in order:
1. Prefer an explicit, provider-labelled title for the interface locale.
2. Use a localized Wikidata/Wikipedia name **only when a unique QID is linked by the work's exact AniList/Bangumi external ID**. Record QID, locale and source separately in `title_external_evidence`—not in the provider-verified `title_localizations` map.
3. If the locale is Chinese and the source has an explicitly labeled name in the other Chinese script, use offline OpenCC as a fallback. Record the conversion in `title_script_conversions`, **never** `title_localizations`.
4. If the same **verified source work ID** (not a title/year heuristic) supplies a suitable nonofficial Han-only infobox alias for a Korean/Japanese original, use the scoped `displayAliases` candidate; convert its Chinese script if required and retain conversion provenance. `displayAliases` is a transient typed source-evidence field, **not** a verified `title_localizations` value or a newly introduced YAML schema field. Persist the chosen title and already-supported aliases/provenance using the existing note codec.
5. Otherwise keep a safe source title. Other unlabelled synonyms are searchable aliases, not verified translations; do not infer a work's identity from its title.

Provider-specific evidence:
- **Bangumi:** `name_cn` is Simplified Chinese, an explicitly labelled infobox title can be Traditional Chinese. Both can be converted when the other script is requested. When the compact search result contains only a Korean/Japanese original title, the user may select it and fetch that same subject ID's full infobox. Only a matching subject's nonofficial Chinese alias is eligible for `displayAliases` (for example Bangumi subject 399671); it must never be promoted to an official localization.
- **AniList:** `english` is official English; `native` is attributed to its native-script locale when `countryOfOrigin` identifies JP, KR, CN, TW or HK. Chinese-origin native titles can use script conversion, with conversion provenance recorded separately. Country-of-origin attribution is not evidence of a separate licensed translation. Neither `romaji` nor `synonyms` provides trustworthy Chinese language attribution for Japanese/Korean-origin works, so do not invent Chinese translations.
- **Open Library:** Work `title` is a fallback, not presumed to be an official Chinese translation. Search's `lang` now follows the interface's language preference (zh-TW/zh-CN → zh, en → en, ja → ja, ko → ko), which influences edition preference but **does not certify the title language**.
- **Manually entered media:** User-entered title is authoritative; the adapter skips manual items entirely.

This contract applies to search results, metadata enrichment, and the initial creation form; no legacy-data action is needed for new imports. If the user changes the suggested title manually before saving, the note stores that exact title and does not falsely claim a script conversion. `title_original`, `title_aliases`, verified `title_localizations`, and actual creators are preserved.

Cross-provider matching by title/year is **not** sufficient evidence to auto-fill verified titles. Legacy title reconciliation can offer potential cross-provider matches for explicit review, but a new import must not silently adopt an unverified match. Machine translation is not currently provided.

## AniList API availability and request contract

AniList's official API documentation (https://docs.anilist.co/guide/rate-limiting and https://docs.anilist.co/guide/considerations) describes a temporary degraded limit of **30 requests/minute**, burst limits, 429 responses with Retry-After, and 403 responses while the API is disabled for stability. AniList may also exceptionally block excessively active IPs. No API client can guarantee availability during an upstream outage.

All AniList GraphQL calls, including search, exact-ID enrichment and manga release links, use the single POST endpoint `https://graphql.anilist.co`. `AniListClient` coalesces duplicate in-flight queries, maintains a bounded response cache and **serializes different-key HTTP calls** with at least 2100 ms between request starts. Search query variants are batched through GraphQL aliases when supported, rather than launching one HTTP request per variant.

For HTTP 403 / GraphQL status 403: do not retry, bypass the upstream restriction or switch to an undocumented proxy. Surface the provider error and stop additional requests from the same client for a 60-second cooldown; queued calls fail without contacting AniList. 429 follows `Retry-After` where provided, otherwise pauses 60 seconds; retry only once when the remaining delay is short enough for interactive use. An interactive request timeout also causes a temporary cooldown, because Obsidian's `requestUrl` has no physical abort capability. 5xx may be retried at most once. Other providers are independent and remain searchable.

This is intentionally **request-load mitigation, not a claim to fix AniList's server-side 403 availability**. Offline unit/contract tests simulate successful calls, 403, 429, timeouts and queued workloads; real-user network conditions and upstream outages require manual observation.

## Unified language evidence via Wikidata / Wikipedia

The title resolver is independent of the metadata provider. First prefer a title explicitly labeled for the selected interface language in the original provider; then look up a **unique Wikidata entity through the exact external work ID**, rather than choosing the first text-search result; then use Chinese script conversion from a reliably labeled Chinese variant; finally retain the source name. English/Japanese/Korean aliases without language attribution are *not* Chinese translations.

The supported Wikidata property mapping is AniList anime `P8729`, AniList manga/light novels `P8731`, Bangumi subjects `P5732`, and Open Library work IDs `P648` (excluding `OL...M` edition and `OL...A` author IDs). The resolver queries WDQS for a unique `QID` (rejecting absent/duplicate matches) and retrieves localized labels and Wikipedia sitelinks with `wbgetentities`. The QID, identifying property, text, locale and source category are recorded as `title_external_evidence` only when that title is chosen. A Wikidata label or Wikipedia article name is **community-curated multilingual naming evidence**, not necessarily an official licensed release title; script-converted variants are labeled separately. The `title_localizations` map remains reserved for provider-labeled variants.

The same identifier-based Wikidata service is used in the **new-note** enrichment flow and the existing-note Title Update **review** flow. The separate legacy-metadata repair flow requests **classification only**, so it does not add Wikidata/Bangumi title lookups for every note being migrated. New-note defaults may adopt a unique QID-linked name; existing notes are *never rewritten automatically*. A title/year-only Bangumi matching heuristic remains a review-only last resort, never a verified cross-provider identity. Manually entered or edited names remain authoritative. If Wikidata is unavailable or has no exact ID link, preserve the provider title rather than inventing a translation.

Do not infer completeness from a name search: not all Wikidata items carry AniList/Bangumi properties. Queries should be narrowly scoped to one external ID, cached by property/ID/locale, and should not be retried aggressively on upstream errors. See [Wikidata data access guidance](https://www.wikidata.org/wiki/Help:Data_access).

## Incremental Settings operations

All four operations in **Updates & cleanup** expose the same scan-scope choice:
- **Only new or unfinished items** (default): skip successful checks whose file mtime/size and operation have not changed. Title checks additionally distinguish target language. Proposed but unconfirmed changes and API failures remain pending. A completed scan that found no reliable translation, no known source or multiple ambiguous matches is checkpointed as **checked with no changes** so the default mode does not repeatedly make the same API requests; these works are always eligible for **Rescan all items**, or automatically after their note changes. User-authored custom titles remain untouched.
- **Rescan all items**: ignore checkpoints and inspect all eligible notes in the configured Library roots.

Checkpoints reside in `.obsidian/plugins/animelist/cleanup-scan-history.json` and are not frontmatter, not part of the note body, and not a record of media activity. Each successful write is checkpointed against the **updated** file version so the new file content is not immediately rescanned. Failed writes, inconclusive provider upgrades and unconfirmed proposals are never marked complete. A separate full scan remains available whenever the upstream metadata source changes. File moves/renames and content edits naturally invalidate path/version-based checkpoints. No scanning runs automatically merely because Settings was opened.

## External media search and identity protocol

The Search API contract distinguishes **discovery** (finding potentially related
results) from **verified identity** (proving two source records are the same).
No note or external ID is changed merely because a candidate ranked highly.

- Initial queries use the original title and the existing season/subtitle variants.
  When the first results are insufficient, Bangumi can receive a bounded set
  of Chinese OpenCC and distinctive substring queries. This is a discovery
  heuristic, not a translation or a synonym dictionary.
- Related provider titles may expand a search after a plausible seed is found.
  Queries and provider requests must be deduplicated; provider-side cooldown,
  rate limits, and network failures remain isolated per source.
- A match on title, original title, year, season, or format **never** establishes
  cross-provider identity. Automatic merging requires an overlapping provider
  identifier, no conflicting identifiers, and compatible media types. Ambiguous
  candidates remain separate. Verified IDs are also required before AniList
  classification can be attached to Bangumi-only works.
- Bangumi Book type 1 covers both novels and manga. Only explicit platform,
  categorization tags, and recognized infobox keys may establish a subtype.
  Unknown subtype results remain candidates; explicit opposite subtypes are
  excluded. Work titles and adaptation tags are not classification evidence.
- A search session preserves the actual expanded queries, undisplayed results,
  per-provider cursors and search category across Load more requests. It does not
  restart pagination from only the user's original string. Provider failures are
  surfaced and must not block successful results from the others.
- Each new UI search receives an **opaque interaction-specific `sessionId`**.
  The Load more API accepts an optional fourth argument with that ID; two
  searches of the same text must never share or replace cursor state. The
  three-argument legacy host call remains supported via the latest query
  session, but UI pagination must always provide the explicit ID. Expired or
  mismatched explicit IDs fail closed rather than silently requesting page N
  from unrelated query state or another user interaction.
- Search first-result progress callbacks must be forwarded through
  `main.ts` to the search service. UI updates from stale queries are ignored;
  subsequent pages use the same verified provider identity deduplication rules,
  including preserving distinct results with no stable provider ID.
- Searches are read-only. In particular, changes to this search layer never
  migrate titles, alter source IDs in existing notes, rename Markdown files,
  or mutate user-owned metadata. Provider-neutral display title selection and
  Wikidata exact-ID title evidence continue to use their existing services.

Limits: substring discovery does not guarantee Google-like semantic search for
all unknown aliases; source API indexing determines whether a partial query
returns the work. Verify recall and request counts against real providers in
Obsidian Test Vault rather than assuming mocked coverage proves availability.

## Interactive search latency and nonofficial Chinese aliases (PR #243 follow-up)

Search latency must not scale linearly with the number of guessed aliases:

- Bangumi and Open Library interactive requests have a 6-second logical
  deadline, with timeout warnings isolated to the affected provider. AniList
  retains its separately configured 5-second timeout and 2100 ms pacing.
  `requestUrl` does not support cancellation, so the physical upstream request
  can continue after the UI timeout. Never automatically retry a timed-out
  request or bypass provider rate limits. A logical deadline bounds user-visible
  waiting per request; it is not a physical network abort.
- Query planning limits first-phase variants to two, Chinese discovery variants to
  two, and cross-language alias variants to three; a non-batching provider executes
  at most two queries per phase concurrently, while AniList can batch up to three
  aliases in one GraphQL operation. Each provider is independent. The same
  AniList client still serializes *physical* requests at least 2100 ms apart;
  never bypass upstream 403/429 protections. The limit is on speculative
  variants, not a guarantee of end-to-end latency.
- Stop discovery after the first sufficiently relevant source candidate. Avoid
  further alias requests to a source that already returned that work.
  When a different source remains unresolved, its supplemental lookup is
  optional and may finish later; the UI displays first-source results immediately
  without replacing the input control or changing focus.
- An upstream Bangumi search can index an infobox alias but only return an
  original Korean title in its compact result payload. Display this hit early.
  When the user selects it, fetch the **same Bangumi subject ID** to obtain its
  full infobox, rather than guessing a different Bangumi/AniList ID.
- If that exact Bangumi record provides an unambiguous Han-only alias while
  the original is Hangul/Kana, the alias may be used as a **nonofficial display
  and newly imported note title**. Keep it in the distinct `displayAliases`
  field, never in provider-verified `localized` or `title_localizations`.
  If OpenCC is used, persist its conversion provenance separately. Existing
  user-owned titles and manually typed names remain authoritative.
- If the exact Bangumi record contains no recognizable Chinese alias, there is
  **no automatic machine translation**: preserve the original title and expose
  other candidates only with their real provenance.
- Display latency still depends on the first responding provider. Do not claim
  a fixed millisecond SLA from mocked requests or confuse first-result time with
  the total time required to finish all optional metadata sources.

Regression tests must verify worst-case request counts, the first-result callback
while a second provider is pending, Korean-origin + Chinese-infobox-alias
selection (Bangumi subject 399671), seasons and subtitles, pagination loading
state, and preservation of the original note metadata.

## UI presentation and interaction protocol

This section is authoritative for AnimeList UI consistency. Metadata, provider identity,
frontmatter and note content remain governed by the preceding storage/API contracts.

- **Shared component ownership:** Common modal actions use `src/ui/ui-primitives.ts`.
  A primary action uses `mod-cta`, a destructive confirmation uses `mod-warning`,
  and other actions remain secondary. Feature-specific icon tools and workspace
  gestures may differ, but must preserve the same focus, disabled and touch states.
- **Media editing:** Search-result collection and editing a saved work use
  `createMediaEditorIdentity` in `src/ui/media-editor-layout.ts` and the existing
  `createMediaEditorFields` in `src/ui/media-form-controls.ts`. The source
  controls only initial values and whether collection or saving is offered.
  Provider classification uses `src/ui/media-classification-fields.ts`.
  Do not introduce another set of parallel fields or validation rules.
- **Covers:** The displayed cover in the editor's identity header is read-only.
  Both manual collection and saved-cover replacement use the accessible
  `createFilePickerControl` button instead of exposing the native file-input
  chrome. Replacement previews stay collapsed until a file is selected;
  opening or canceling an editor must never write images to the vault.
  Reset, cleanup and size/type validation retain their existing data-service contracts.
- **Dialog dimensions:** Confirmation dialogs use a compact, centered modal,
  not a wide outer dialog with a narrow content column. Standard editing dialogs
  can remain wider, while Timeline and image workspaces retain task-dependent
  geometry. The CSS contract is scoped under `.animelist-modal` rather than
  modifying Obsidian's global `.modal` or other plugins.
- **Text layout:** Long CJK titles, arbitrary aliases, file names and paths
  must not overflow any dialog. Use `min-width: 0` in flex/grid children;
  prefer natural line breaks and `overflow-wrap: anywhere` only for unbroken
  strings. Do not globally apply `word-break: break-all` or force a narrow
  description container inside a wide modal.
- **Accessibility and input:** Functional buttons are real `button` elements,
  including file-picker triggers. Focus-visible indication, disabled semantics,
  keyboard activation and a touch target of at least 44 px on narrow layouts
  are required. Modals retain Obsidian's native focus and Escape lifecycle.
- **Styling:** `styles/ui-primitives.css` and `styles/media-editor-layout.css`
  are bundled through `scripts/style-bundle.mjs`. Consume Obsidian CSS variables
  instead of introducing fixed theme colors. `styles.css` is generated and may
  only be changed with `npm run styles:build`.
- **Evidence:** Layout changes require a Chromium check at 320/390/768/1200 px,
  real DOM interaction checks for covered workflows, and manual Test Vault
  verification of Obsidian theme/locale/modal lifecycle on desktop and mobile.
  A passing isolated browser fixture does not establish parity with the live app.

See `docs/TESTING.md` for fast/full test tiers. Full tests must run for a
release or merge gate; targeted/smoke tests are for routine iteration.
